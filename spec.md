# Court Vision — AI-ассистент баскетбольного скаута

## Продукт

Backend-сервис для аналитики NBA: отвечает на вопросы об игроках и матчах на естественном языке, генерирует скаутинг-отчёты, сравнивает игроков и присылает ежедневные дайджесты результатов. Под капотом — LLM-агент с доступом к статистической базе и RAG-поиском по текстовому корпусу (статьи, правила, заметки). Сервис демонстрирует полный стек современного AI-бекенда и проектируется с расчётом на продакшн.

## Ключевые возможности

- **Q&A с цитатами** — вопросы в свободной форме, ответы с ссылками на источники (RAG); отдельный режим «эксперт по правилам» по rulebook NBA
- **Скаутинг-отчёты** — структурированный разбор игрока/матча из сырой статистики (structured output, streaming), сохранение и поиск по отчётам
- **Агент с инструментами** — сам решает, какие данные достать: `get_player_stats`, `compare_players`, `search_corpus`, `search_reports`, `find_similar_players`
- **Сравнение игроков** — side-by-side с перцентилями по лиге и radar-чартом
- **Похожие игроки** — статистический отпечаток игрока (вектор из нормализованной статистики) → поиск ближайших через pgvector
- **Пересказ матча** — LLM-нарратив любого исторического матча из его box score
- **Ежедневный дайджест** — фоновый sync результатов + LLM-сводка в in-app ленте; персонализация через вотчлист (подписка на игроков/команды). Email/Telegram-каналы — v2
- **Eval-сьют** — 30–50 эталонных вопросов, LLM-as-judge, регрессионные прогоны при смене промптов/моделей
- **Дашборд стоимости** — страница в UI: токены, стоимость, латентность LLM-запросов

v2 (backlog): прогнозы исходов матчей (статистическая модель, LLM только объясняет), таблица положения команд, email/Telegram-дайджест. См. [docs/roadmap.md](docs/roadmap.md).

## Технологии

- **Язык/фреймворк:** Python, FastAPI
- **UI:** SPA — Vite + React + TypeScript, Tailwind поверх собственных дизайн-токенов; стриминг через SSE. Тонкая витрина: сложность остаётся в API
- **БД:** PostgreSQL + pgvector (единая база: реляционка + векторный поиск), JSONB для сырых payload'ов
- **LLM:** litellm как транспорт/нормализация провайдеров (Anthropic / Gemini / Groq); свой агентный цикл, фолбэк-политика, кеширование ответов, подсчёт стоимости токенов
- **Поиск:** гибридный (векторный + полнотекстовый tsvector), реранкинг
- **Асинхронщина:** arq + Redis (воркеры, крон-задачи, rate limiting, кеш)
- **Auth:** Clerk (managed IdP): готовые компоненты входа на фронте, JWKS-валидация в FastAPI
- **Наблюдаемость:** structlog, трейсинг LLM-вызовов в Langfuse (токены, латентность, стоимость), таблица `llm_usage` для продуктовых агрегатов
- **Инфра:** Docker Compose, CI (GitHub Actions); деплой в конце v1 — Railway (бэкенд) + Vercel (SPA)

Детали: [docs/architecture.md](docs/architecture.md), план работ: [docs/roadmap.md](docs/roadmap.md).

## Данные

- **Исторические (основной массив):** Kaggle-датасеты NBA (матчи, box scores, статистика игроков), сезоны с 2005-06, без play-by-play → разовый seed в Postgres
- **Свежие:** balldontlie API, free tier (teams/players/games, 5 req/min) → ежедневный sync 1–3 запросами, паттерн cache-aside
- **Текстовый корпус для RAG:** Wikipedia (игроки, команды), официальный rulebook NBA (PDF), собственные заметки → chunking → embeddings → pgvector
- **Абстракция:** интерфейс `DataProvider` с реализациями `LocalProvider` (Postgres) и `BalldontlieProvider` (внешний API, fallback)
