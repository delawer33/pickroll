# Дизайн-система Court Vision

Визуальный язык и структура интерфейса. Обязателен для всех фронтенд-задач: этот документ —
источник правды, код — его следствие.

Смежное: [conventions.md](conventions.md) — правила кода, [architecture.md](architecture.md) —
системные решения, [CONTEXT.md](../CONTEXT.md) — доменный язык.

Наглядная реализация направления и всех четырёх структур: [design/reference.html](design/reference.html)
(откройте в браузере, есть переключатель светлой и тёмной темы).

**Язык интерфейса — английский.** Все строки UI, состояния ошибок и пустых экранов —
по-английски. Документация, комментарии и доменные термины остаются русскими: в коде понятие
называется Диалогом, на экране — `Conversation`. Соответствие — §10.

## 1. Что проектируем

Инструмент скаута. Пользователь смотрит на данные и ведёт диалог с Агентом, поэтому интерфейс
плотный, тихий и быстро читаемый; всё, что не помогает принять решение, не занимает пикселей.

Фронт — тонкая витрина: он ничего не считает. Значит визуальная система обязана **принимать
готовые числа и не врать про них** — приоритет у выравнивания цифр, точности шкал и честных
подписей.

## 2. Направление: Register

**Печатный статистический ежегодник.** Холодная бумага, сетка, которую видно, нулевой радиус,
один красный.

- **Сетка нарисована, а не подразумевается.** Структуру задают линейки: 2px под шапками
  колонок и над статистической строкой, 1px между строками, вертикальные линейки в таблицах.
  Это отсылка к печатной справочной таблице и одновременно самый дешёвый способ держать
  плотность без карточек.
- **Ни одной скруглённой формы.** Радиус 0 везде; круг только у аватара.
- **Тени нет.** Тень существует только чтобы сказать «это слой над страницей» (поповер, диалог).
- **Холодный нейтральный сток.** Не крем и не тёплый бежевый — они читаются как штамп (§3).
- **Один акцент.** Красный `#cc2200` в светлой теме. Категориальные цвета живут только внутри
  данных и с акцентом не конкурируют.
- **Одна гарнитура.** Archivo на всё, ось ширины вместо второго семейства (§5).

Ориентир по тону: плотность и клавиатурность продуктовых инструментов вроде Linear плюс подача
печатной статистической страницы. Не «спортивный сайт с фото», не «SaaS-лендинг», не лонгрид.

## 3. Anti-slop: чего не делаем

Список действует как правило ревью.

| Не делаем | Почему |
|---|---|
| Градиенты как фон блока, особенно лилово-синие | первый визуальный признак генерации |
| Inter, Roboto, Open Sans, Poppins, Montserrat | самые частые шрифты в обучающих данных |
| Скругления и «pill» | направление построено на нулевом радиусе |
| Тени на карточках контента | разделяем линейкой; тень только у оверлеев |
| Стеклянный блюр как стиль | декор без функции |
| Эмодзи как иконки | иконки — Lucide, один набор, один вес |
| Ряд KPI-плиток «метка / число / зелёная дельта» | самый узнаваемый дашборд-штамп; вместо него статистическая строка (§7.1) |
| Три карточки в ряд с иконкой-кругом сверху | лендинговый штамп внутри продукта |
| Центрированный текст внутри приложения | центрируется только пустое состояние и форма входа |
| Цветной фон блока для «важности» | важность — размер, вес, положение |
| Больше одного акцентного оттенка в UI | акцент один |
| Тёплый крем со контрастным дисплейным серифом и терракотой | узнаваемая связка сама по себе |
| Акцентная планка слева на скруглённой карточке | тот же штамп; планка допустима только как индикатор активного роута |
| Анимация появления списков, reveal on scroll | приложение, а не презентация |
| Тонкий вес на мелком кегле, «воздушный» серый текст | нечитаемо на плохом экране |
| Заглушки «Lorem», «Feature 1» | моки используют реальные имена игроков и реальные числа |

Дополнительно **никогда**: цвет как единственный носитель смысла; двойная ось Y; радужные
шкалы; оттенок в середине диверджентной шкалы; число на каждой точке графика.

Нарушение по осознанной причине описывается в PR. Молчаливое нарушение — блокирующий
комментарий.

## 4. Токены: устройство

Два уровня, оба — CSS-переменные, единственный источник правды.

```
ramp   --cv-slate-1 … --cv-slate-12, --cv-red-*, --cv-series-*   сырые ступени, hex
role   --cv-paper, --cv-surface, --cv-ink, --cv-line, --cv-accent  семантика
```

**Компоненты используют только роли.** Сырая ступень или hex в компоненте — ошибка ревью. Тема
переключается переопределением ролей; ramp не меняется. Префикс `--cv-` обязателен — он
отделяет наши токены от переменных Tailwind и Clerk.

Роли ступеней взяты по модели Radix Colors (1–2 фоны, 3–5 состояния компонента, 6–8 границы,
9–10 сплошная заливка, 11–12 текст), значения свои; зависимости на библиотеку цветов нет.

### Слой Tailwind

Tailwind v4, CSS-first. Ramp объявляется статикой в `@theme`, роли — переменными на `:root` и
`[data-theme="dark"]`, и пробрасываются в утилиты через **`@theme inline`**: утилита
компилируется в `var(--cv-surface)`, а не в скопированное значение, и продолжает следовать теме.

```
shared/styles/tokens.css   ramp + роли
shared/styles/theme.css    @theme inline — проброс ролей в утилиты
```

Итог: `bg-surface`, `text-ink-muted` и `var(--cv-surface)` — одно значение по определению.

## 5. Токены: значения

### 5.1 Нейтральный ramp

Светлая тема — Slate, тёмная — Night.

| Ступень | Роль | Light | Dark |
|---|---|---|---|
| 1 | плоскость страницы | `#e8eaeb` | `#0f1113` |
| 2 | поверхность листа | `#ffffff` | `#15171a` |
| 3 | фон компонента | `#f1f2f3` | `#1c1f23` |
| 4 | hover | `#e9ebec` | `#22262a` |
| 5 | active / selected | `#dfe2e3` | `#292e33` |
| 6 | линейка между строками | `#dfe3e5` | `#23272b` |
| 7 | линейка вокруг блока | `#b6bcbf` | `#363c41` |
| 8 | тяжёлая линейка (2px) | `#101315` | `#e8eaeb` |
| 11 | текст низкого контраста | `#636a6e` | `#848c91` |
| 12 | текст высокого контраста | `#101315` | `#eef0f1` |

Промежуточная роль текста: `ink-secondary` `#3c4245` / `#bcc2c6`.
Поверхность оверлея: `#ffffff` / `#1b1e22`, плюс тень.

Измеренный контраст к ступени 2: ink 16.7 / 14.9; ink-secondary 9.7 / 9.0; ink-muted 5.5 / 5.3.

`ink-muted` подобран так, чтобы держать 4.5:1 **на всех трёх фонах — плоскости страницы,
листе и заливке.** Плоскость страницы (ступень 1) — самый тёмный светлый фон, и метки на ней
живут: рейка Evidence и заголовки секций. Проверять muted-текст только против листа
недостаточно.

### 5.2 Акцент

| Роль | Light | Dark | Проверка |
|---|---|---|---|
| `--cv-accent` (фокус-ринг, индикатор роута, рамка тега) | `#cc2200` | `#ff4a26` | не-текст, ≥3:1 |
| `--cv-accent-solid` (фон залитой кнопки) | `#cc2200` | `#cc2200` | белый текст 5.53:1 |
| `--cv-accent-text` (ссылки, акцентный текст) | `#b81f00` | `#ff6a4a` | 6.49 / 6.34 |

**Фокус-ринг** — 2px `--cv-accent` с отступом 2px. Линейки 6/7 дают 1.6–2.1:1 — этого хватает
разделителю и не хватает фокусу, поэтому фокус никогда не рисуется границей.

### 5.3 Статусы

Текстовые статусы и метки на графиках — разные токены: тексту нужно 4.5:1, метке 3:1.

| Роль | Light текст | Dark текст | Метка (обе темы) |
|---|---|---|---|
| good | `#046904` | `#5fd45f` | `#0ca30c` |
| warning | `#8a5a00` | `#f0b429` | `#fab219` |
| critical | `#b02020` | `#f07070` | `#d03b3b` |

Статус всегда идёт с иконкой и подписью. Статусные оттенки зарезервированы: «серия 4» их не
получает никогда.

### 5.4 Типографика

Одна гарнитура: **Archivo** — переменный гротеск, оси `wght` 100–900 и **`wdth` 62–125**,
OFL 1.1. Самохостится через `@fontsource-variable/archivo`, только латиница (язык интерфейса
английский, имена игроков и команд латинские). Обращений к CDN нет.

Ось ширины заменяет второе семейство: дисплейные ступени набираются сжатыми и тяжёлыми, метки
колонок — узкими, поэтому короткая шапка не требует уменьшения кегля.

Идентификаторы (имена инструментов, id, ключи цитат) — системный моно
`ui-monospace, SFMono-Regular, Menlo, monospace`. Второй веб-шрифт не подключается.

| Токен | Размер / интерлиньяж | Вес, ширина, трекинг | Применение |
|---|---|---|---|
| `display` | `clamp(28px, 3.4vw, 36px)` / 1.0 | 900, `wdth 84`, −0.03em | имя игрока, заголовок экрана |
| `stat` | 19 / 1.0 | 900, `wdth 86`, −0.02em, `tnum` | значение в статистической строке |
| `title` | 19 / 1.25 | 700, −0.01em | заголовок секции, тема Диалога |
| `heading` | 15 / 1.35 | 600 | заголовок панели, раздел отчёта |
| `read` | 15 / 1.6 | 400 | ответ Агента, тело отчёта |
| `body` | 14 / 1.5 | 400 | UI-текст |
| `body-sm` | 12.5 / 1.45 | 400 | ячейки таблиц, вспомогательный текст |
| `label` | 12 / 1.3 | 500 | подписи полей, бейджи |
| `micro` | 10 / 1.2 | 600, `wdth 88`, +0.15em, uppercase | шапки колонок, метки, оси |
| `mono` | 12 / 1.5 | 400 | имена инструментов, id |

Правила: длина строки в тексте для чтения — **68ch max**; `tnum` включён на всех табличных
колонках, осях и статистических значениях и выключен в абзацах; `wdth < 100` применяется только
к дисплейным ступеням и `micro` — сжатый body ошибка ревью.

### 5.5 Линейки

Рулёж — часть направления, и он параметризован, поэтому обратим одним токеном.

| Токен | Значение | Где |
|---|---|---|
| `--cv-rule-heavy` | `2px` ступень 8 | под шапкой колонок, над статистической строкой |
| `--cv-rule` | `1px` ступень 7 | вокруг блока, под заголовком секции |
| `--cv-rule-row` | `1px` ступень 6 | между строками таблицы |
| `--cv-rule-v` | `1px` ступень 6 | вертикальные линейки в таблицах |

Зебры нет: ритм держат линейки. Горизонтальные и вертикальные линейки вместе — подпись
направления, отключать их по вкусу нельзя.

### 5.6 Ритм и плотность

Шаг 4px, шкала `0, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80`. Промежуточных значений нет;
`padding: 13px` — ошибка ревью.

| Величина | Значение |
|---|---|
| строка таблицы (норма / компакт) | 34px / 28px |
| высота контрола (sm / md / lg) | 26 / 30 / 38px |
| внутренний отступ панели | 16px, 20px у панелей с заголовком |
| внешний отступ экрана | 24px, 16px при ширине < 640px |
| левая рейка (развёрнута / свёрнута) | 240 / 56px |
| верхняя полоса | 46px |
| колонка чтения | 68ch |
| ширина контента | 1120px; таблицы — во всю ширину |

### 5.7 Радиус, тени, движение

Радиус **0** везде; круг только у аватара.

Тени две, только для слоёв над страницей:

```
--cv-shadow-overlay: 0 1px 2px rgba(16,19,21,.07), 0 8px 24px -6px rgba(16,19,21,.15);
--cv-shadow-dialog:  0 2px 4px rgba(16,19,21,.09), 0 24px 48px -12px rgba(16,19,21,.24);
```

В тёмной теме те же геометрии с `rgba(0,0,0,.55)` и линейкой ступени 6 сверху. Тень на карточке
контента, кнопке или инпуте запрещена.

| Движение | Длительность / кривая | Что |
|---|---|---|
| `--cv-motion-instant` | 0ms | меню, командная палитра, поповер |
| `--cv-motion-fast` | 110ms `ease-out` | hover, цвет, границы |
| `--cv-motion-enter` | 170ms `cubic-bezier(.2,.8,.25,1)` | сообщение в ленте, тост |
| `--cv-motion-panel` | 260ms `cubic-bezier(.2,.8,.25,1)` | боковая панель, свёртывание рейки |

Высокочастотное не анимируется; анимация объясняет связь элемента с источником. Курсор печати —
единственный бесконечный цикл. Под `prefers-reduced-motion: reduce` всё сводится к 0ms, курсор
становится статичным.

## 6. Данные и графики

### 6.1 Движок

Три слоя, в порядке предпочтения — **чем меньше движка, тем лучше**.

| Слой | Что рисуем | Почему |
|---|---|---|
| **CSS/DOM, без библиотеки** | перцентильные полосы, спарклайны в строке, полоски в ячейках | это списки полос, а не графики: осей нет, шкала линейна. Дешевле и по коду, и по байтам |
| **Recharts** | линии по сезонам, сгруппированные столбики, scatter похожих игроков, radar профиля | шкалы и тултипы уже есть; нам остаётся стилизация токенами |
| **Свой SVG** | тепловая карта | в Recharts нет heatmap-примитива. Только по факту отсутствия примитива |

Recharts закрывает `RadarChart`, `ScatterChart`, `LineChart`, `BarChart`, `ReferenceLine`
(базовая линия 50-го перцентиля), `ErrorBar`, `Brush` и `Customized` — люк для своей метки
внутри графика, без выхода из библиотеки.

Цвет и типографика во всех слоях из токенов: CSS-переменные работают в SVG-атрибутах, поэтому
`stroke="var(--cv-series-1)"` — норма, а hex внутри компонента графика — ошибка ревью. Тултип
свой (`content={<CvTooltip/>}`), чтобы носить наши поверхности, тени и шрифты.

Recharts тянет `@reduxjs/toolkit` и `react-redux` как внутренние зависимости. Правило «глобальный
стейт не вводим» это не нарушает, но: графики грузятся лениво (`React.lazy` на роут, не в общий
чанк), а диапазон пинуется через `pnpm.overrides` на RTK 2.x — на 1.8.x у Recharts рантайм-краш.

### 6.2 Интерактивность — по умолчанию

График в HTML уже интерактивен; отказ от этого — регресс.

| Форма | Интерактив |
|---|---|
| линия, область | crosshair и общий тултип по ближайшей X-точке, подчёркнутая конечная точка |
| столбики, точки, ячейки | тултип на метку, зона захвата больше метки |
| radar | тултип на вершину оси со значениями всех серий по этой оси |
| stat-строка без графика | единственная форма без ховера |

Плюс одинаково для всех: **легенда** при ≥2 серий (при одной серии название говорит, что это);
до 4 серий дополнительно прямые подписи; **табличное представление** переключателем; **фильтры
одной строкой над графиком** с состоянием в search params, чтобы ссылка воспроизводила картинку;
таблица как гарантированный доступный путь к тем же числам; `isAnimationActive={false}` под
`prefers-reduced-motion` — ховер остаётся, он обратная связь.

Табличное представление обязательно не для галочки: в светлой теме три слота ниже 3:1 к
поверхности, и правило компенсации (§6.3) выполняется подписями или таблицей. Без неё палитра
нелегальна.

### 6.3 Категориальная палитра

Порядок слотов получен перебором всех 40320 перестановок восьми оттенков: отобраны проходящие
все жёсткие проверки в обеих темах на наших поверхностях, среди них взят максимум минимального
ΔE соседних пар. Первый слот закреплён за брендовым оранжевым, который валидируется в обеих
темах.

| Слот | Оттенок | Light | Dark |
|---|---|---|---|
| 1 | orange | `#e8590c` | `#e8590c` |
| 2 | aqua | `#1baf7a` | `#199e70` |
| 3 | blue | `#2a78d6` | `#3987e5` |
| 4 | yellow | `#eda100` | `#c98500` |
| 5 | magenta | `#e87ba4` | `#d55181` |
| 6 | green | `#008300` | `#008300` |
| 7 | violet | `#4a3aa7` | `#9085e9` |
| 8 | red | `#e34948` | `#e66767` |

Результаты (OKLab ΔE ×100, поверхности `#ffffff` / `#15171a`): соседние пары — CVD ΔE **10.4**
light / **11.6** dark при цели ≥8; нормальное зрение **19.6** / **19.3** при пороге ≥15.

В светлой теме aqua (2.82:1), yellow (2.17:1) и magenta (2.69:1) ниже 3:1 к поверхности —
действует **правило компенсации**: такой график обязан иметь прямые подписи значений либо
табличное представление.

**Ограничение на формы «любая пара рядом»** (scatter, bubble, малые кратные — то есть scatter
похожих игроков): при проверке всех пар безопасны только **первые три слота**. Четвёртый ставит
рядом yellow и orange, и пара проваливает порог. Значит на scatter максимум три цветовые группы;
дальше — «Прочие» или малые кратные, не расширение палитры.

Слоты назначаются по порядку и **никогда не цикличны**: девятая серия — это «Прочие». Цвет
следует за сущностью, а не за её рангом: фильтр, меняющий число серий, не перекрашивает выживших.

### 6.4 Шкалы величины и полярности

- **Sequential** (магнитуда) — один оттенок blue, светлое→тёмное, `--cv-seq-100 … --cv-seq-700`.
  Оранжевый на эту роль не идёт: он занят слотом 1.
- **Diverging** (полярность вокруг базы: перцентиль относительно лиги, разница со средним) —
  **blue ↔ red**, нейтральный серый в середине. Привычная для спорта зелёно-красная шкала
  отклонена: она нечитаема при дейтеранопии, а blue↔red совпадает с метафорой «холодно/жарко».

### 6.5 Формы

| Что показываем | Форма | Почему |
|---|---|---|
| Перцентили относительно лиги | горизонтальные диверджентные полосы от 50-го (CSS) | полярность, а не магнитуда |
| Сравнение 2–3 игроков по профилю | radar (Recharts) | сравнение формы; предел 3 игрока (§6.3) |
| Сравнение по конкретному показателю | сгруппированные столбики | radar врёт на абсолютных величинах |
| Похожие игроки | scatter по двум главным осям отпечатка | ≤3 цветовые группы |
| Динамика по сезонам | линия 2px, маркеры ≥8px | change-over-time |
| Один ключевой показатель | статистическая строка, без графика | иногда правильный ответ — не график |
| Box score | таблица | таблица и есть визуализация |

Спецификация метки: линии 2px, маркеры ≥8px, 2px зазор цветом поверхности между заливками,
прямые подписи выборочно. Текст на графике носит текстовые токены, не цвет серии: значения,
подписи и легенда в `ink` / `ink-secondary` / `ink-muted`, идентичность несёт цветная метка рядом.

Тёмная тема — выбранные ступени, а не автоматическая инверсия.

## 7. Структуры экранов

Одна композиция на все экраны — источник шаблонности. Поэтому структур четыре, и каждая
отвечает своей задаче. Все четыре носят Register без исключений.

| Структура | Экраны |
|---|---|
| **Sheet** | страница Игрока, Скаутинг-отчёт, Пересказ матча |
| **Worktable** | Диалог |
| **Grid** | справочник Игроков, Сравнение игроков |
| **Spine** | Дайджест, история Диалогов |

### 7.1 Sheet — одна типографическая колонка

Ни карточек, ни панелей, ни сайдбара: одна колонка, работу границ делают линейки и воздух.

Статистика набирается **строкой**, а не рядом плиток: `29.6 PTS · 12.7 REB · 10.2 AST · 66.1 TS%`,
значения ступенью `stat`, метки — `micro`. Строка обрамлена 2px линейкой сверху и 1px снизу.
Порядок: kicker (`micro`) → имя (`display`) → подпись → статистическая строка → проза → ruled
заголовок секции → содержимое.

### 7.2 Worktable — диалог и провенанс

Две панели с независимым скроллом. Слева Диалог, справа рейка **Evidence**, которая накапливает
каждый результат Инструмента со штампом источника и времени. Данные здесь — провенанс, который
можно проверить.

- реплика пользователя — `body`, выключена вправо, фон ступени 3, ширина по контенту до 80%;
- ответ Агента — `read`, колонка 68ch, без фона и рамки; стриминг обозначает курсор, не декор;
- **карточка Evidence** — заголовок с именем инструмента (`mono`), источником и длительностью,
  дальше результат: таблица, полосы или цитата. Это главная витрина продукта, поэтому получает
  собственный вес — линейка вокруг и фон ступени 3, а не серый мелкий текст. Отгружено пока не
  так: поток не несёт ни результата, ни длительности, и карточка показывает аргументы вызова —
  см. [deferred.md](deferred.md);
- **цитата** — надстрочный числовой маркер в тексте, `accent-text`; клик подсвечивает карточку
  Evidence, из которой утверждение взято;
- **курсор печати** — 2px×1em блок цвета `accent`, мигание 1.1s;
- **ошибка** — иконка `critical`, заголовок и текст из Problem Details (`title` + `detail`),
  кнопка `Retry`. Никогда не «Something went wrong»: сообщение говорит, что случилось и что делать.

### 7.3 Grid — таблица как экран

Таблица от края до края: без контейнера и отступов страницы, строки 28px, залипшие шапка и
колонка имени, вертикальные линейки. Тулбар сверху — фильтры, сезон, режим, счётчик строк;
переносится на узком экране, не обрезается.

Выбранная строка раскрывается **на месте** полосой с перцентилями, а не уводит на другой экран.
Сортировка — иконка в шапке, состояние в search params. Диалог — докнутая полоса снизу.

На узком экране таблица не превращается в карточки: горизонтальный скролл внутри своего
контейнера при залипшей первой колонке. Страница по горизонтали не скроллится никогда.

### 7.4 Spine — хронология

Одна вертикальная линейка, даты как якоря слева, записи нанизаны в порядке времени: Дайджест,
Пересказ матча, Ответ, Скаутинг-отчёт. Ни карточек, ни колонок. Запись: тип (`micro`) →
заголовок → примечание → строка чисел. Сегодняшний якорь помечен акцентом.

На узком экране дата встаёт над записью, линейка прижимается к краю.

### 7.5 Состояния

Каждый экран обязан иметь четыре: загрузка (скелетон в форме контента, не спиннер по центру),
пусто (одна строка что это + одно действие), ошибка (Problem Details + повтор), частичный отказ
(данные есть, деградация подписана). Пустое состояние — единственное место, где текст центрируется.

## 8. Каркас и роуты

Постоянная левая рейка 240px (свёртывается в 56px, уходит в drawer при ширине < 900px), верхняя
полоса 46px с заголовком экрана, действиями и `UserButton`, дальше область контента. Рейка
выбрана вместо верхней навигации: Диалогов много и их истории нужна вертикаль, продукт
клавиатурный.

Заголовки групп рейки (`ASSISTANT`, `DATA`, `FEED`) — `micro`, не кликабельны. Активный пункт:
фон ступени 5 и 2px акцентная планка слева — единственное место, где планка разрешена (§3).

| Путь | Экран | Структура | Срез |
|---|---|---|---|
| `/` | редирект на `/chat` | — | #6 |
| `/chat` | новый Диалог | Worktable | #6 |
| `/chat/$conversationId` | Диалог | Worktable | #6, SSE в #8 |
| `/history` | история Диалогов | Spine | позже |
| `/players` | справочник Игроков | Grid | позже |
| `/players/$playerId` | карточка Игрока | Sheet | позже |
| `/compare` | Сравнение игроков (`?players=`) | Grid | позже |
| `/reports` | список Скаутинг-отчётов | Spine | позже |
| `/reports/$reportId` | Отчёт | Sheet | позже |
| `/digest` | Дайджест | Spine | позже |
| `/watchlist` | Вотчлист | Grid | позже |
| `/usage` | Дашборд стоимости | Sheet | позже |
| `/sign-in/*` | вход (Clerk) | — | готово |

Режим «Эксперт по правилам» — не роут, а режим композера внутри `/chat`: отдельная страница
дублировала бы весь Диалог ради одного переключателя.

Состояние экрана, которое должно переживать перезагрузку и шариться ссылкой (выбранные игроки,
сезон, фильтры, сортировка, поиск), живёт **в search params**. Это прямая причина выбора
TanStack Router: типизированные search params.

## 9. Инвентарь компонентов

Готовые библиотеки компонентов не используются. Интерактив — примитивы Radix UI со своей

`Select`/`Combobox`, `Dialog`, `DropdownMenu`, `Tabs`, `CommandPalette`, `SeasonPicker`,
`PlayerSearch`, `WatchlistToggle`.

В `shared/ui` живут только примитивы без домена. Компонент, знающий про Игрока или Диалог, —
в своём `features/*`.

## 11. Чеклист перед мержем

- [ ] Ни одного hex, px-кегля или цвета вне токенов в компоненте; только роли, не ступени ramp.
- [ ] **Тест обесцвечивания:** выключаем акцент — иерархия экрана всё ещё читается.
- [ ] Отступы только из шкалы 4px; радиус 0.
- [ ] Обе темы проверены глазами; тёмная не инверсия.
- [ ] Фокус видим с клавиатуры на каждом интерактивном элементе, порядок табов логичен.
- [ ] Muted-текст держит 4.5:1 на плоскости страницы, на листе и на заливке — все три.
- [ ] Числа в столбцах — `tnum` и выключка вправо.
- [ ] Ничего из списка §3.
- [ ] Новая категориальная палитра или серия — прогнан валидатор, результат в PR.
- [ ] У графика есть ховер, легенда при ≥2 серий и табличное представление.
- [ ] `prefers-reduced-motion` уважается.
- [ ] На 360px страница не скроллится по горизонтали; широкий контент скроллится внутри себя.
