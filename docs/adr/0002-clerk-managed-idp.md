# Clerk как managed IdP вместо собственного JWT-стека

Auth нужен ради вотчлиста и персональных дайджестов. Ручная JWT-логика (пароли, хеши, refresh-токены) отвергнута как commodity-код, который в проде не пишут; self-hosted IdP (Keycloak) — как слишком тяжёлый для нашего деплоя (+600MB RAM Java-сервис). Выбрали Clerk: пароли не хранятся вообще, фронт получает готовые компоненты входа (кастомизируются под наши дизайн-токены), FastAPI валидирует токены по публичному JWKS — стандартный прод-паттерн «resource server доверяет IdP». Free tier 10k MAU; локальный запуск работает без секретов (publishable key и JWKS публичны). Последствие: миграция на другой IdP при необходимости — через экспорт пользователей Clerk.
