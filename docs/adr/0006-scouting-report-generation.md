# Скаутинг-отчёт: structured output потоком, проверка по входу, неизменяемая строка

Скаутинг-отчёт генерирует модель, а читает скаут, который будет опираться на его цифры. Поэтому отчёт — не текст, а JSON по фиксированной схеме (`summary`, `archetype`, `strengths[]`/`weaknesses[]`, `stat_profile`, `comparables[]`, `outlook`), и всё, что в нём можно проверить без модели, проверяется кодом.

Решения:

- **Один вход — один источник фактов.** Сервис собирает вход из тех же функций, что и Инструменты (сезонные средние, Перцентили, Похожие игроки), и кладёт в промпт список `allowed_metric_keys`. Игрок резолвится по имени один раз; дальше сервисы ходят по `Player`, а не по имени (`player_percentiles`, `similar_players_for`) — повторная Резолюция полного имени упала бы на тёзке. Сезон без Отпечатка не ошибка: `fingerprint: null`, сопоставимых игроков нет.
- **Structured output через общий транспорт со стримингом.** Тот же `transport.stream`, что у агента и судьи (`response_format` с JSON Schema), поэтому учёт `llm_usage`, классификация ошибок и трейсинг не дублируются. Частичный JSON разбирает pydantic (`TypeAdapter.validate_json(..., experimental_allow_partial=True)`) в модель с необязательными полями — без `trailing-strings`, чтобы раздел появлялся целиком, когда модель его закончила («по разделам»), а ключи метрик не мигали обрезанными. Каждый снапшот заменяет предыдущий; повтор начинается с пустого.
- **Схема без ограничений вроде `min_length`.** Strict-режим шлюзов отвергает такие ключевые слова (то же решение, что у вердикта судьи). Смысловые проверки живут в `check_grounding`: разделы непусты, у каждого пункта есть метрика, метрика есть во входе **и имеет значение** (метрика `null` в ту эпоху не считалась — утверждение про неё выдуманное), сопоставимый игрок — пара (имя, сезон) из Похожих игроков входа.
- **Один повтор, потом доменная ошибка.** Невалидный ответ возвращается модели вместе со списком нарушений; вторая неудача — `ReportGenerationFailed` (502, `report-generation-failed`), отчёт не сохраняется и эмбеддинг не считается. Третьей попытки нет: две подряд — это вход или модель, а не случайность. Исход каждой попытки — событие `reports.validation` в structlog; повтор идёт под операцией `reports.generate_retry`, поэтому доля невалидных с первого раза читается из `llm_usage` без отдельной таблицы. Отдельных «маркерных» строк с нулевыми токенами в `llm_usage` нет: строка там — это вызов.
- **Неизменяемость держит база.** Отсутствие эндпоинтов правки недостаточно: триггер `BEFORE UPDATE` на `scouting_reports` отвергает любой UPDATE. Новый взгляд на игрока — новая строка (`INSERT`), версия схемы и модель-генератор записаны в строку, чтобы старые отчёты читались своей схемой.
- **Владелец — условие запроса, не проверка.** Каждое чтение и поиск фильтруются по `clerk_user_id` в самом SQL; чужой отчёт неотличим от несуществующего (404). `ToolContext` несёт id пользователя хода, модель его не передаёт и подменить не может.
- **`search_reports` — точный скан по косинусу, не HNSW.** Отчётов у одного пользователя десятки, а фильтр по владельцу после обхода графа молча терял бы выдачу (то же решение, что для Похожих игроков, ADR-0005). Эмбеддится «имя, сезон. архетип. резюме», чтобы запрос про игрока находил отчёт, в резюме которого фамилии может не быть. Поиск ранжирует, но не отсекает: порога близости нет (шкала зависит от эмбеддера), поэтому промпт Инструмента требует сверять `player`/`season` найденного.
- **`create_scouting_report` внутри цикла не стримит.** Снапшоты некому показывать; Инструмент вычерпывает генерацию, сохраняет отчёт своими короткими транзакциями и возвращает резюме со ссылкой. Транзакция чтения закрывается до генерации — иначе соединение пула висело бы десятки секунд.

Отвергнуто:

- **Свободный текст и разбор регулярками** — метрики в утверждениях не проверить, а «стримится по разделам» превращается в нарезку строки.
- **Ручной парсер частичного JSON** — готовое решение есть в pydantic, а свой парсер ломается на вложенных массивах.
- **Хранить отчёт с возможностью правки** — личный артефакт, на который скаут ссылается; правка задним числом ломает «что я писал тогда». Нужен новый — заводится новый.
- **Строки-счётчики в `llm_usage` (`reports.valid`/`reports.invalid`)** — нарушают инвариант «строка = вызов провайдера» и портят суммы по операции.
