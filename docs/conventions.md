# Конвенции кода и принципы проектирования

Обязательны для всех спринтов и всех агентов, работающих с кодовой базой. Системные решения — в [architecture.md](architecture.md).

## Организация кода

- **Package by feature (vertical slices).** Backend: `players/`, `agent/`, `corpus/`, `reports/`, `digest/`, ... — внутри модуля свои `router.py`, `service.py`, `models.py`, `schemas.py`. Frontend: `features/chat/`, `features/comparison/`, ... + `shared/` (ui-примитивы, API-клиент, токены). Граница модуля = граница домена.
- **Интерфейсы только у настоящих швов.** Абстракции (Protocol/ABC) допустимы только там, где существует или предрешена вторая реализация: `DataProvider`, LLM-транспорт. Репозитории-прослойки, use-case-классы и порты «на всякий случай» запрещены. См. [ADR-0003](adr/0003-vertical-slices-no-ceremony.md).
- **Сервисы — функции в модуле**, принимающие зависимости (сессию БД) явно. Классы — только при реальном состоянии или полиморфизме.

## Backend

- **DI:** нативный FastAPI `Depends` для request-scoped (сессия, текущий пользователь); объекты уровня приложения (LLM-клиент, настройки) — через lifespan/`app.state`. Внешние DI-контейнеры не используются.
- **БД:** SQLAlchemy 2.0 async, миграции Alembic с первого дня. Сессия per-request; unit of work = HTTP-запрос: commit на границе запроса, rollback при исключении, сервисы не коммитят.
  - **Исключение — стриминговые эндпоинты.** Тело SSE-ответа генерируется после того, как обработчик вернул ответ, и транзакция запроса висела бы открытой всё время, пока отвечает LLM. Такие эндпоинты берут не сессию, а фабрику (`SessionFactoryDep`) и нарезают себе короткие транзакции сами: одну на приём вопроса, по одной на вызов Инструмента, одну на сохранение ответа. Образец — `conversations/streaming.py`.
- **Конфигурация:** pydantic-settings, 12-factor — всё через env; в git только `.env.example`; никаких `if ENV == "prod"` в бизнес-коде.
- **Промпты — как код:** файлы в репозитории, изменение промпта = PR + прогон eval-сьюта.

## API

- Префикс `/api/v1` с первого дня.
- Ошибки — RFC 9457 Problem Details; единый exception handler, сервисы кидают типизированные доменные исключения.
- Wire-формат — snake_case; TS-типы фронтенда генерируются из OpenAPI (`openapi-typescript`), руками не пишутся.
- SSE — типизированные события (`token`, `tool_call`, `tool_result`, `citation`, `done`, `error`), описанные в OpenAPI-моделях.
- Пагинация: cursor-based для растущих списков (дайджесты, отчёты); offset — для статичных справочников.

## Frontend

- Серверное состояние — TanStack Query; глобальный клиентский стейт-менеджер не вводится без доказанной потребности.
- Роутинг — TanStack Router (типизированные роуты).
- Компоненты: headless-примитивы Radix UI + собственная стилизация. Готовые библиотеки компонентов не используются.
- Дизайн-токены — CSS-переменные как единственный источник правды; Tailwind читает их из конфига.
- Графика: Recharts по умолчанию (лениво, отдельным чанком); CSS/DOM там, где «график» — это список полос; свой SVG только при отсутствии примитива в Recharts. Ховер, легенда и табличное представление обязательны.
- Визуальный язык, токены, палитра графиков и структуры экранов — [design-system.md](design-system.md); наглядная реализация — [design/reference.html](design/reference.html).

## Тестирование

- **Testing trophy:** основная масса — интеграционные тесты через HTTP с настоящим Postgres (testcontainers). Подмена на SQLite запрещена (pgvector, tsvector).
- Юнит-тесты — для чистой логики: перцентили, нормализация отпечатков, чанкинг.
- **LLM:** в тестах мокается только граница litellm (подставные ответы с tool-call'ами) — тестируется механика цикла (маршрутизация инструментов, фолбэк, стриминг, учёт стоимости). Качество ответов проверяет eval-сьют, не тесты. Живые LLM-вызовы в CI запрещены.
- Frontend: Vitest + Testing Library для компонентов с логикой; Playwright — smoke-сценарий (спринт 5).
- Покрытие измеряется, жёсткий порог не ставится.

## Тулинг и процесс

- Python: `uv` (пакеты, lock), `ruff` (линт + формат), `mypy --strict`. Frontend: `pnpm`, eslint + prettier, `tsc --noEmit` в CI.
- pre-commit и CI используют одни и те же конфиги — локально и в CI проверки идентичны.
- Trunk-based: короткоживущие ветки → PR в `main`, зелёный CI обязателен (тесты, mypy, ruff, tsc).
- Conventional commits (`feat:`, `fix:`, `chore:`, ...).
