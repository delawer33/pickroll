# Спринт 1 — Ходячий скелет: зафиксированные решения

Результат grill-сессии 2026-08-17. Вход для детального проектирования спринта. Состав спринта и демо-критерий — в [roadmap.md](../roadmap.md); конвенции обязательны ([conventions.md](../conventions.md)).

## Чат

- **Многоходовый с персистентностью с первого дня**: таблицы `conversations` и `messages`, агент получает полную историю диалога. Список диалогов в UI — минимальный.
- Термин «Диалог (Conversation)» добавлен в [CONTEXT.md](../../CONTEXT.md).

## Данные и схема БД

- **Датасет**: кандидат — [eoinamoore/historical-nba-data-and-player-box-scores](https://www.kaggle.com/datasets/eoinamoore/historical-nba-data-and-player-box-scores) (построчные box scores игрок-матч, обновляется еженощно); подтвердить структуру колонок при реализации. Запасной: szymonjwiak/nba-traditional. Фильтр: сезоны ≥ 2005-06 (~26 тыс. матчей, ~600–800 тыс. строк box score).
- **Сезонные агрегаты считаются на лету** из строк box score (GROUP BY по индексу `(player_id, season)`); никаких предагрегированных таблиц и materialized view — единственный источник правды. Пересматривать только при измеренной медленности перцентилей в спринте 3.
- **Seed**: скачивание через kagglehub с запиненной версией датасета; загрузка через COPY; идемпотентный one-off скрипт (`uv run python -m ...`), запускается после подъёма Compose.
- **Тесты/CI**: маленькая фикстура (несколько игроков/сезонов, ~1–2 МБ) того же формата коммитится в git; её грузит тот же seed-код — тестируется и сам seed.
- **Таблицы спринта 1**: `teams`, `players`, `games`, box score строки, `conversations`, `messages`, `llm_usage`. Alembic с первого дня.
- **Таблицы `users` нет**: пользователь идентифицируется `clerk_user_id` (опаковая строка из токена). Локальная таблица появится только при появлении собственных атрибутов пользователя.
- **`llm_usage` пишется с первого спринта** (одна строка на LLM-вызов: токены, стоимость, латентность) — история для дашборда спринта 5.

## Инструмент `get_player_stats`

- **Вход**: `player_name` (свободный текст; LLM инструктирован передавать имя латиницей), `season` — опционален.
- **Резолюция имени внутри инструмента**: общая функция-резольвер (pg_trgm). Ниже порога сходства → структурный ответ «не найдено + ближайшие кандидаты», агент самокорректируется вторым вызовом. Неоднозначность → список кандидатов. Резольвер переиспользуется будущими инструментами (compare_players и др.).
- **Выход**: резолвнутая идентичность игрока + при заданном сезоне — средние, тоталы и число игр за сезон; без сезона — таблица по всем сезонам карьеры (с 2005-06).
- Проверка: интеграционные тесты резольвера (кириллица → структурная ошибка; `Lebron` → матч) + демо-вопрос.

## Агентный цикл и LLM

- **Один провайдер в спринтах 1–4**: модель задаётся env-строкой litellm. Дефолт: `anthropic/claude-haiku-4-5`. Ошибка провайдера → SSE-событие `error`. Автоматический фолбэк — спринт 5 (зафиксировано в roadmap).
- SSE-протокол — по конвенциям: `token`, `tool_call`, `citation`, `done`, `error`.
- **Langfuse опционален локально**: нет ключей → колбэк не регистрируется, система работает.

## Auth

- **Весь `/api/v1` под токеном** (кроме health). JWKS-URL/источник конфигурируется; интеграционные тесты генерируют RSA-пару и подписывают токены сами — auth-код тестируется по-настоящему, без байпасов и без живого Clerk в CI.

## Каркас

- Монорепо: `backend/` + `frontend/` в корне, `docker-compose.yml` рядом.
- CI: GitHub Actions, джобы backend (ruff, mypy --strict, pytest+testcontainers) и frontend (eslint, tsc, vitest), path-фильтры. Пре-коммит и CI — одни конфиги.
- UI спринта 1: app shell с Clerk-логином, страница чата со стримингом, дизайн-токены (CSS-переменные) + Tailwind.
- Локальное демо зависит от облака: Clerk, LLM-провайдер, Langfuse (опционально) — осознанно (см. ADR-0002).

## Не делаем в спринте 1

- Фолбэк LLM-провайдеров, кеширование ответов, rate limiting (спринт 5).
- Предагрегация статистики, materialized views.
- Таблица `users`, профили пользователей.
- Гейм-логи в выходе `get_player_stats`.
