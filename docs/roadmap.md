# Roadmap

Работа над v1 разбита на 5 спринтов. Каждый спринт — вертикальный срез: заканчивается работающей end-to-end фичей с демо-критерием. Детальную архитектуру каждого спринта проектирует отдельный агент; демо-критерий — его definition of done.

Деплой в облако выполняется в конце v1 (спринт 5); до этого вся система живёт и демонстрируется локально через Docker Compose.

Закрытый спринт помечается ✅ и строкой под заголовком: дата, issue, состояние демо. Что из спринта осознанно не доделано — в [deferred.md](deferred.md), а не здесь: roadmap отвечает на «что дальше», а не «что мы про себя знаем».

Начиная со спринта 2 рядом с демо-критерием стоит **метрика** — измеримый критерий готовности. Демо показывает, что фича живая; метрика — что она работает не только на демо. Метрики будущих спринтов — черновики, уточняются при планировании спринта.

## Спринт 1 — Ходячий скелет ✅

_Закрыт 2026-08-23 ([#1](https://github.com/delawer33/pickroll/issues/1), срезы [#2](https://github.com/delawer33/pickroll/issues/2)–[#8](https://github.com/delawer33/pickroll/issues/8)). Демо проходит: ответ про Леброна в 2012-13 — 26.8 очка, цифры сверены с Postgres. Отложенное вынесено в [deferred.md](deferred.md), auth-hardening — в [#9](https://github.com/delawer33/pickroll/issues/9)._

Монорепо (backend + frontend), Docker Compose, CI, схема БД + seed Kaggle (сезоны с 2005-06, box scores), auth через Clerk, дизайн-токены и каркас UI, litellm + минимальный агентный цикл с одним инструментом `get_player_stats`, чат с SSE-стримингом, Langfuse подключён.

**Демо:** локально поднять систему, залогиниться, спросить «сколько в среднем набирал Леброн в 2012-13» — получить стриминговый ответ из БД.

## Спринт 2 — RAG и цитаты

Расширение seed до основания NBA (первым срезом: спайк качества ранних данных, при грязи до ~1970 — отступ на промежуточную границу; семантика «метрика не считалась в ту эпоху» в `get_player_stats` — не ноль). Корпус: rulebook NBA + Wikipedia (игроки и команды из базы, статьи о сезонах) через идемпотентный CLI-пайплайн — чанкинг по структуре документа с локатором для цитирования, эмбеддинги через шлюз (модель и размерность в env, имя модели хранится в чанке). Гибридный поиск: pgvector + tsvector, слияние RRF, реранкер (Jina) как выключаемая ступень — включается по ключу и только если улучшает метрику. Инструмент `search_corpus` с фильтром источника (он же — «эксперт по правилам», без UI-режима). Цитаты двух уровней: проекция чанков в карточке Evidence и маркеры в тексте ответа с картой «маркер → чанк», сохраняемой в Реплике. Ретривал-eval: золотой набор запросов с ожидаемым локатором.

**Демо:** вопрос про правило → ответ со ссылками на конкретные секции rulebook; вопрос об эпохе до 2005 — ответ с цитатами Wikipedia и статистикой из расширенного seed.

**Метрика:** recall@10 и MRR на золотом наборе в CI, с разбивкой по источникам; порог фиксируется после первого прогона бейзлайна. Валидность маркеров цитат — наблюдаемый счётчик, не гейт.

## Спринт 3 — Скаутские инструменты

Скаутинг-отчёты (structured output, стриминг, сохранение + `search_reports`), сравнение игроков с перцентилями и radar-чартом, статистический отпечаток + `find_similar_players`, пересказ матча.

**Демо:** «сравни Карри и Лиллэрда» → side-by-side с графикой; «найди похожих на Дончича» → список с объяснением.

**Метрика (черновик):** доля отчётов, прошедших валидацию схемы; перцентили сверены детерминированным тестом против SQL; золотой набор пар «заведомо похожи / непохожи» для `find_similar_players`.

Запасной ход: если спринт перегружен, пересказ матча сдвигается в спринт 4.

## Спринт 4 — Живые данные и дайджест

Интерфейс `DataProvider` (Local / Balldontlie, cache-aside), arq-крон ежедневного sync, генерация дайджеста + in-app лента, вотчлист с персонализацией дайджеста.

**Демо:** утром в ленте — сводка вчерашних матчей, команды из вотчлиста сверху.

**Метрика (черновик):** операционные условия — «вчерашние матчи в базе к утру» и «дайджест сгенерирован» как проверяемые факты, не ощущения.

## Спринт 5 — Качество, эксплуатация, деплой

E2E eval-сьют: LLM-as-judge поверх золотого набора спринта 2 (правильность и процитированность ответов, прогон в CI), кеширование LLM-ответов, rate limiting, фолбэк-политика LLM-провайдеров (в спринтах 1–4 — один провайдер через env), дашборд стоимости в UI, hardening и полировка UX, деплой: Railway (API, воркер, Postgres, Redis) + Vercel (SPA).

**Демо:** PR со сменой промпта → CI показывает регрессионный прогон; система доступна по прод-URL.

**Метрика (черновик):** оценка LLM-судьи на золотом наборе; стоимость ответа и cache hit rate — наблюдаемые.

## v2 (backlog)

- **Прогнозы исходов матчей** — статистическая модель (Elo + форма + отдых + домашний фактор) поверх исторических данных; LLM только объясняет прогноз, никогда не называет вероятности сам. Усиливается платным тиром balldontlie (свежая статистика игроков; травмы — только в верхнем тире).
- **Таблица положения команд**, вычисляемая из результатов.
- **Каналы дайджеста:** email (Resend) и Telegram-бот в дополнение к in-app ленте.
